# ADR slyy-downstream-branding: Slyy downstream branding

- Status: Accepted
- Date: 2026-11-18

## Context

This repository ships PI-Desktop as **Slyy** (Wapsol GmbH). The Rust host-core
and the Pi agent harness keep their upstream contracts; only user-, agent- and
tool-visible identity changes, with compatibility for the old names below. Slyy must not collide with the earlier Slyy Desktop app or with a
PI-Desktop installed on the same machine, and its installation identity must
never change after the first release, or auto-update and stored data break.

## Decision

Frozen identity (guarded by `apps/desktop/test/slyy-identity-contract.test.mjs`):

| Concern | Value |
| --- | --- |
| Shown name (`APP_NAME`, `CFBundleName`, shortcuts) | `Slyy` |
| Installation name (`APP_INSTALLATION_NAME` → `app.setName`, userData, safeStorage) | `Slyy Gen2` |
| Bundle / app id (`appId`, `APP_ID`, Windows AUMID) | `ai.slyy.desktop.gen2` |
| Product / executable file name | `Slyy Gen2` (`slyy-gen2` on Linux) |
| NSIS GUID | `72db17f1-8935-5bae-870f-999d4b7621a6` |
| Data directory (passed to host-core via `PI_DESKTOP_DATA_DIR`) | `~/.slyy-gen2` (dev `~/.slyy-gen2-dev`) |
| Update feed and release assets | GitHub `mySlyy/releases` (public), cache `slyy-gen2-updater` |
| macOS signing | repo variables `SLYY_APPLE_TEAM_ID`, `SLYY_MAC_SIGNING_IDENTITY` |

The "Gen2" suffix is a clean cut from the earlier Slyy Desktop app: no shared
bundle id, app file, keychain entry or data folder.

Host-core fallback data dir (`PI_DESKTOP_DATA_DIR` unset) is `~/.slyy-gen2`
too (`state::DEFAULT_DATA_DIR_NAME`). `~/.pi-desktop` is never read: Slyy
does not share data with a PI-Desktop install.

Renamed identifiers. Slyy only produces the new form; the old one is still
accepted so existing data, clients and links keep working:

| Identifier | New | Still accepted |
| --- | --- | --- |
| Worktree branch namespace | `slyy/<id>` | stored `pi-desktop/<id>` rows resume, merge, clean up; their subagent branches stay the session's own. Only a branch named `slyy` blocks isolation. |
| MCP control server name | `slyy` | — (informational) |
| MCP generic invoke tool | `slyy_invoke` | `pi_desktop_invoke` on `tools/call` only (unlisted alias, same confirm gate). The app writes no client configs; external clients may have the old name. |
| MCP token header | `X-Slyy-Token` | `X-Pi-Desktop-Token` (same constant-time token check; `Authorization: Bearer` preferred) |
| Session links | `slyy://session/<id>` | `pi-desktop://session/<id>` parsed everywhere. Neither scheme is registered with the OS (plain text resolved in-app), so nothing hijacks a separately installed PI-Desktop. |
| Workspace ignore file | `.slyyignore` | `.pi-desktopignore` (both apply when present) |
| Imported plugin wrapper marker | `// Generated by Slyy:` | `// Generated by PI-Desktop:` |
| OpenCode identity | `x-opencode-client: slyy`, `User-Agent: slyy/<ver>` | — (attribution only, like pi's `pi`; OpenCode does not allowlist it) |

Plugin catalog: `https://hub.slyy.ai/catalog.json` (official channel); package
resolution, review tickers/lists and the write-a-review page derive their
origin from it (`hub.slyy.ai/api/v1/...`, `hub.slyy.ai/plugins/<id>#reviews`).
No request goes to the upstream plugin center. The device id keeps its internal
`pi-desktop.device.v1:` prefix and is sent only to the hub.

Kept on purpose (upstream contracts, harness or remote hosts depend on them):
`@pi-desktop/*` package names, `PI_DESKTOP_*` environment variables,
`pi-startup:`/`pi-genui:` protocols, localStorage keys, the
`pi-desktop-host-core` binary, `~/.pi` agent paths, remote-host paths under
`~/.pi-desktop/pi-host` (pi-host `config.ts`, `provider-import.ts`,
`host-operations.ts`, `cli.ts`, and the SSH bootstrap/supervisor scripts),
IPC channels `pi-desktop/<area>/<op>`, `window.piDesktop`, plugin manifest
field `minPiDesktop`, publisher fallback `pi-desktop`
(`plugins/install.rs`), `.pi-desktop.lock`, skill ids `pi-desktop/imagegen`
and `pi-desktop/visualize`, `#pi-desktop-overlays`, `--pi-desktop-locale`,
test-only temp prefixes (`pi-desktop-instructions-`, `pi-desktop-dev-`), the
device-id namespace `pi-desktop.device.v1:`, and the `SELF_APP_KEYS` entries.

`SELF_APP_KEYS` (`crates/host-core/src/computer/policy.rs`) keeps the
upstream keys and adds `ai.slyy.desktop.gen2` and `slyy`, so computer use
keeps refusing the app's own helper windows after the rename.

Visual identity follows slyy.ai through `apps/desktop/src/styles/tokens.css`
only: ink `#0a0a0a`, paper `#f4f4f2`, accent `#2b3bff` (dark-theme tint
`#7a85ff` for AA contrast), square radius ladder, Hanken Grotesk and Martian
Mono (bundled via Fontsource). UI locales: English and German (formal "Sie").

Release: the upstream CNB (cnb.cool) release mirror workflow is removed.
The source repository `mySlyy/slyy-desktop` is private, and users,
electron-updater and the remote `pi-host` bootstrap cannot read releases from a
private repository. `release.yml` therefore builds in `mySlyy/slyy-desktop` and
publishes each `v<version>` release to the public repository `mySlyy/releases`
(token secret `SLYY_RELEASES_TOKEN`). `electron-builder` `publish`,
`resources/app-update.yml`, `GITHUB_RELEASES_REPO` (`@pi-desktop/shared`: in-app
Releases link and `pi-host` downloads) and the README download links point
there. This moved the update feed once, before the first release, so no
installed client is stranded. Source and repository metadata stay on
`mySlyy/slyy-desktop`. In-app bug reports (`GITHUB_REPO`, derived from
`GITHUB_RELEASES_REPO`) and `package.json` `bugs.url` open issues on
`mySlyy/releases`, which carries the same `bug_report.yml` form, because the
private source repository returns 404 to users.

macOS signing on tag builds is opt-in through the repository variable
`SLYY_MAC_SIGNING_ENABLED=true` (requires the Apple secrets). Until it is set,
tag releases ship unsigned macOS builds as GitHub pre-releases whose notes say
so; Windows builds are unsigned either way.

## Consequences

- No in-place upgrade path from PI-Desktop or the earlier Slyy Desktop; a
  one-time data import is planned separately.
- Windows builds stay unsigned until a code-signing certificate exists; set
  `win.publisherName` then so electron-updater verifies installers.
- Unsigned macOS builds cannot update in-app (Squirrel.Mac requires a valid
  signature). The updater never offers pre-releases (`allowPrerelease =
  false`), so while every release is a pre-release no platform updates
  in-app; users install from `mySlyy/releases` manually.
- User bug reports land in `mySlyy/releases`; maintainers triage them there
  and open a linked issue in `mySlyy/slyy-desktop` when code work starts
  (GitHub cannot transfer issues from a public to a private repository).
  0.23.0-beta.2 still opens the private repository; later builds use
  `mySlyy/releases`.
- macOS releases are Apple silicon (arm64) only. The Intel x64 lane of
  upstream D285 / ADR 0145 is removed from `release.yml`: one fewer macOS
  runner per release and about 270 MB less per release in `mySlyy/releases`.
  `latest-mac.yml` is electron-builder's single arm64 feed, checked before
  publish. Intel Macs get no build; local `dist:mac -- --x64` still works
  for testing, and the Rosetta hint (E2E-240) stays for such builds.
- Private vulnerability reporting is enabled on `mySlyy/releases`;
  `SECURITY.md` and the issue picker link there for the same reason.
